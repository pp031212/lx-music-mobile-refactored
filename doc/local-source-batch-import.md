# 本地音源脚本批量导入

入口：设置 → 基本设置 → 自定义源管理 → 导入 → 本地导入。

启用「使用系统文件选择器」时，可以点选一个 `.js` 文件，也可以长按第一个文件后继续选择并确认。关闭该设置时，「本地导入」打开应用内文件选择器，支持单选。在线导入仍从同一个导入菜单进入。

行为参考 `lx-music-desktop-ui-refactor` 的 `UserApiModal.vue`：

- 按选择顺序逐个读取、导入与保存，单个文件失败不会停止整批。
- 单个文件导入成功时显示简短提示。多选或导入遇到问题时，汇总成功、失败、跳过数量，并显示失败文件名与原因。
- 最多保留 20 个自定义源。达到上限后不再读取剩余文件，直接报告跳过数量。
- 批量处理期间阻止重复点击该入口；核心层也串行处理不同入口的音源修改，防止超限或覆盖数据。
- 仅导入 `.js` 文件，允许大小写扩展名；去除 UTF-8 BOM，拒绝空脚本。
- 单个文件读取上限为 9 MB；文件在原生后台线程中逐个读取，不将整批脚本同时载入内存。
- 同一次选择的重复 URI 会跳过。不同 URI 下的相同内容仍按独立音源导入，与单文件行为一致。
- 导入不会自动启用音源，仍需在自定义源设置中选择。

## Android 适配

项目已有文件库的 `multi` 选项仅设置了多选请求，但其回调只读取 `Intent.getData()`，
没有处理多选使用的 `ClipData`。因此在现有 `UtilsModule` 下新增 `LocalSourcePicker`，
统一处理单 URI、多 URI、取消选择和文件读取，不修改 `node_modules` 或第三方依赖。

系统授权读取被选中的文档 URI，不需要申请整盘读取权限，不复制临时文件。
由于增加了原生方法，使用此功能必须重新构建并安装 APK，单独更新 JS bundle 不够。

## 验证

```sh
npm run test:user-api
```

测试包括失败后继续、数量上限、重复 URI、空文件、BOM、按序执行、不同入口并发、
删除与导入的顺序、保存失败后不留下虚假音源。

真机检查：从同一个本地入口取消、单选、多选、选择非 `.js` 文件或混选有效与无效脚本，
检查已有 19/20 个源时的限制和重启后的数据保留，再关闭系统文件选择器验证应用内单选，并检查在线导入。
